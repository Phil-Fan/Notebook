# 64. 最小路径和

!!! abstract "题单坐标"
    **Hot 20 · 第 14 类「多维动态规划」** ｜ 难度：中等 ｜ 标签：`数组` `动态规划` `矩阵`

    一句话套路：`dp[i][j]` 是从左上角走到 `(i, j)` 的最小路径和，等于当前格子加上「从上来」和「从左来」的较小值。

## 题干

> [力扣 64. 最小路径和](https://leetcode.cn/problems/minimum-path-sum/)

给定一个包含非负整数的 `m x n` 网格 `grid`，请找出一条从左上角到右下角的路径，使得路径上的数字总和为最小。

说明：每次只能向下或者向右移动一步。

**示例 1**

```text
输入：grid = [[1,3,1],[1,5,1],[4,2,1]]
输出：7
解释：因为路径 1→3→1→1→1 的总和最小。
```

**示例 2**

```text
输入：grid = [[1,2,3],[4,5,6]]
输出：12
```

**提示**

- `m == grid.length`
- `n == grid[i].length`
- `1 <= m, n <= 200`
- `0 <= grid[i][j] <= 200`

## 思路

只能往右或往下，所以进 `(i, j)` 的路径只有两条：从 `(i-1, j)` 下来，或从 `(i, j-1)` 过来。设 `dp[i][j]` 为走到这一格的最小和：

$$dp[i][j] = grid[i][j] + \min(dp[i-1][j],\ dp[i][j-1])$$

第一行没有「上面」，只能从左边累加；第一列没有「左边」，只能从上面累加。`dp[0][0] = grid[0][0]`。

因为所有数非负，没有「绕路反而更小」的情况，这个局部选择就是全局最小。如果格子里有负数，公式仍然对——转移并没有用到非负——但题目保证了非负。

**走一遍示例 1。**

原网格：

```text
1 3 1
1 5 1
4 2 1
```

dp：

```text
1  4  5
2  7  6
6  8  7
```

`(0,1) = 3+1 = 4`，`(0,2) = 1+4 = 5`。`(1,1)` 从上来是 4、从左来是 2，取 2 再加 5，得到 7。`(1,2)` 取 min(5, 7)+1 = 6。`(2,2)` 取 min(6, 8)+1 = 7。路径 `1→3→1→1→1` 对应 dp 右下角的 7；`1→1→5→2→1` 也是 7。

## 代码（带注释）

> 按力扣提交格式写：一个 `Solution` 类。只用内置类型。

=== "主推：原地写回网格"

    ```python
    class Solution:
        def minPathSum(self, grid: list[list[int]]) -> int:
            m, n = len(grid), len(grid[0])
            for j in range(1, n):
                grid[0][j] += grid[0][j - 1]
            for i in range(1, m):
                grid[i][0] += grid[i - 1][0]
                for j in range(1, n):
                    grid[i][j] += min(grid[i - 1][j], grid[i][j - 1])
            return grid[m - 1][n - 1]
    ```

    每个格子只依赖上方和左方，而那两格已经是「走到那里的最小和」，不会再被用到原来的 `grid` 值。额外空间是 $O(1)$。函数返回之后原网格已经被改掉，调试时如果还要看输入，就用下面的二维表。

=== "对照：另开 dp"

    ```python
    class Solution:
        def minPathSum(self, grid: list[list[int]]) -> int:
            m, n = len(grid), len(grid[0])
            dp = [[0] * n for _ in range(m)]
            dp[0][0] = grid[0][0]
            for j in range(1, n):
                dp[0][j] = dp[0][j - 1] + grid[0][j]
            for i in range(1, m):
                dp[i][0] = dp[i - 1][0] + grid[i][0]
                for j in range(1, n):
                    dp[i][j] = grid[i][j] + min(dp[i - 1][j], dp[i][j - 1])
            return dp[m - 1][n - 1]
    ```

    和公式一一对应。`1 × 1` 的网格两层循环都不进，直接返回唯一的格子。

## 复杂度

| 写法 | 时间 | 空间 | 什么时候用 |
|:-----|:-----|:-----|:-----------|
| 原地 | $O(mn)$ | $O(1)$ | 默认，输入可以改 |
| 二维 dp | $O(mn)$ | $O(mn)$ | 讲解、要保留原网格 |
| 枚举所有路径 | $O(\binom{m+n}{m})$ | $O(m+n)$ | 只用来说明路径条数 |

`m, n ≤ 200`，格子数 $4 \times 10^4$，两版都是线性于格子数。

## 易错点

- **第一行也去读 `dp[-1]`**：Python 里 `dp[-1]` 是最后一行，不会报错，但数值是错的。首行首列必须单独累加。
- **`min` 之后忘了加当前格子**：转移变成了「来路的最小值」，路径和把这一格漏了。示例 1 的右下角会得到 6 而不是 7。
- **允许向上或向左**：题目只允许向右、向下。一旦允许四个方向，转移就有环，不能按行优先直接填。
- **原地版和「另开 dp」混在同一次推导里**：原地版的 `grid[i-1][j]` 已经是路径和，不是原来的格子值。对照公式时用二维版。
