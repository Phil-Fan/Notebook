# 动态规划 | Dynamic Programming

!!! abstract "Hot 20 · 第 13 类"
    **什么时候想到它**：问题能拆成「前 i 个 / 以 i 结尾」的子问题，且子问题会重复出现。
    **核心动作**：**先把状态含义用一句话说死**，再写转移，最后补边界和枚举顺序。

## 套路

1. **状态**：`dp[i]` 是「前 i 个」还是「以 i 结尾」？
   - 单词拆分、背包用「前 i 个」；
   - LIS、最大子数组用「以 i 结尾」。
2. **转移**：枚举「最后一步 / 最后一段」。139 就是枚举最后一段词 `w`，要求 `dp[i-|w|]` 为真且 `s[i-|w|:i] == w`。
3. **边界**：`dp[0] = True`（空串是空拼接）、不可达状态用 `-inf` / `False` 占位。
4. **顺序**：依赖更小下标 → 从小到大扫；依赖上一层 → 外层枚举层数（如 188 的 `t`）。

判定 / 计数 / 最优化三类 dp 骨架一样，区别只在转移里用 `any` / `sum` / `min`。

## 易错点

- 状态含义没定死就动笔，必然写着写着乱掉。
- 边界漏掉空串 / 空数组（`s == ""` 返回 `True`）。
- 复杂度里要算上切片和比较的代价：139 是 $O(n m L)$，不是 $O(nm)$。
