# 回溯 | Backtracking

!!! abstract "Hot 20 · 第 9 类"
    **什么时候想到它**：要从一棵选择树里收集所有合法方案，而且「不合法」能在走到叶子之前就看出来。
    **核心动作**：做选择 → 递归 → 撤销选择。剪枝写在递归之前，别等收集答案时再过滤。

## 套路

1. 用一个 `path` 记下当前走到哪。长度够了（或满足收集条件）就把 `path` 的拷贝放进答案。
2. 每一层只尝试**现在还合法**的选择。括号生成里：左括号没用完才能加 `(`，右括号数量不超过左括号才能加 `)`。
3. 递归返回后把刚才的选择弹掉，兄弟分支才能从同一个前缀接着试。
4. 收集答案时拷贝一份。直接把 `path` 放进列表，后面的 `pop` 会把已经收下的方案改掉。

搜索树的大小往往是指数，剪掉一条非法分支，就少掉它下面的整棵子树。$n$ 很小（括号生成 $n \le 8$）时，剪枝后的叶子数就是卡特兰数，可以接受。

## 易错点

- 忘记撤销（`path.pop()`），下一条分支带着上一条的尾巴。
- 答案里放的是 `path` 本身而不是 `path[:]` / `"".join(path)`，最后所有方案都变成空。
- 剪枝条件写成「走到头再判断合法性」，复杂度从卡特兰数退回 $2^{2n}$。
