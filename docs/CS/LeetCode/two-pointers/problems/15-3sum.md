# 15. 三数之和

!!! abstract "题单坐标"
    **Hot 20 · 第 2 类「双指针」** ｜ 难度：中等 ｜ 标签：`数组` `双指针` `排序`

    一句话套路：先排序，固定一个数 `nums[i]`，剩下两个数用左右指针去凑 `-nums[i]`，命中后三处都跳过相邻重复值。

## 题干

> [力扣 15. 三数之和](https://leetcode.cn/problems/3sum/)

给你一个整数数组 `nums`，判断是否存在三元组 `[nums[i], nums[j], nums[k]]` 满足 `i != j`、`i != k` 且 `j != k`，同时还满足 `nums[i] + nums[j] + nums[k] == 0`。请你返回所有和为 `0` 且不重复的三元组。

答案中不可以包含重复的三元组。

**示例 1**

```text
输入：nums = [-1,0,1,2,-1,-4]
输出：[[-1,-1,2],[-1,0,1]]
解释：
nums[0] + nums[1] + nums[2] = (-1) + 0 + 1 = 0
nums[1] + nums[2] + nums[4] = 0 + 1 + (-1) = 0
nums[0] + nums[3] + nums[4] = (-1) + 2 + (-1) = 0
不同的三元组是 [-1,0,1] 和 [-1,-1,2]。
注意，输出的顺序和三元组的顺序并不重要。
```

**示例 2**

```text
输入：nums = [0,1,1]
输出：[]
```

**示例 3**

```text
输入：nums = [0,0,0]
输出：[[0,0,0]]
```

**提示**

- `3 <= nums.length <= 3000`
- `-10^5 <= nums[i] <= 10^5`

## 思路

排序之后，三元组里最小的那个数一定出现在更靠左的位置。于是外层只枚举这个最小数 `nums[i]`，内层在 `(i, n)` 上做对撞：

- 目标和是 `-nums[i]`。
- `nums[left] + nums[right] < -nums[i]`：左指针右移，和才会变大。
- `nums[left] + nums[right] > -nums[i]`：右指针左移，和才会变小。
- 相等：记下这一组，然后两侧同时内收，并跳过和刚记下的值相同的邻居。

排序把「无序里找三个数」变成「有序区间上的单调移动」，内层从 $O(n^2)$ 降到 $O(n)$。

**去重有三处，缺一处就会交重复解。**

1. 外层：`i > 0` 且 `nums[i] == nums[i-1]` 时跳过。同一个最小数只当一次「固定值」。
2. 命中之后左指针：`nums[left] == nums[left-1]` 就继续右移。
3. 命中之后右指针：`nums[right] == nums[right+1]` 就继续左移。

第 2、3 处必须写在「已经收下这一组、指针已经迈出一步」之后。在迈步之前比，比的是自己，会把刚找到的解自己跳掉，或者把还没看过的下一个不同值跳掉。

`nums[i] > 0` 就可以停：后面全是更大的正数，三数之和不可能再是 0。

**走一遍示例。** `nums = [-1,0,1,2,-1,-4]`，排序后 `[-4,-1,-1,0,1,2]`。

| i | 固定值 | left / right | 和 | 动作 |
|:--|:-------|:-------------|:---|:-----|
| 0 | -4 | 1(-1) / 5(2) | -3 | 和太小，left → 2 |
| 0 | -4 | 2(-1) / 5(2) | -3 | left → 3 |
| 0 | -4 | 3(0) / 5(2) | -2 | left → 4 |
| 0 | -4 | 4(1) / 5(2) | -1 | left 追上 right，这一轮结束 |
| 1 | -1 | 2(-1) / 5(2) | 0 | 记下 `[-1,-1,2]`，两侧内收 |
| 1 | -1 | 3(0) / 4(1) | 0 | 记下 `[-1,0,1]`，随后 left ≥ right |
| 2 | -1 | — | — | 与 `nums[1]` 相同，跳过 |
| 3 | 0 | 4(1) / 5(2) | 3 | 和太大，right 左移后与 left 相遇 |
| 4 | 1 | — | — | 固定值已经大于 0，结束 |

答案是 `[[-1,-1,2],[-1,0,1]]`。

## 代码（带注释）

> 按力扣提交格式写：一个 `Solution` 类。只用内置类型。

```python
class Solution:
    def threeSum(self, nums: list[int]) -> list[list[int]]:
        nums.sort()
        n = len(nums)
        ans: list[list[int]] = []
        for i in range(n):
            if nums[i] > 0:
                break
            if i > 0 and nums[i] == nums[i - 1]:
                continue
            left, right = i + 1, n - 1
            while left < right:
                total = nums[i] + nums[left] + nums[right]
                if total == 0:
                    ans.append([nums[i], nums[left], nums[right]])
                    left += 1
                    right -= 1
                    while left < right and nums[left] == nums[left - 1]:
                        left += 1
                    while left < right and nums[right] == nums[right + 1]:
                        right -= 1
                elif total < 0:
                    left += 1
                else:
                    right -= 1
        return ans
```

外层 $n$ 次，内层左右指针一共最多走 $n$ 步，加上排序是 $O(n^2)$。`[0,0,0]` 会在 `i = 0` 时命中一次，随后 `i = 1, 2` 因为与前一个固定值相同被跳过，不会交出三份 `[0,0,0]`。

## 复杂度

| 写法 | 时间 | 空间 | 什么时候用 |
|:-----|:-----|:-----|:-----------|
| 排序 + 双指针 | $O(n^2)$ | $O(1)$（不计答案） | 默认，面试写这一版 |
| 三重循环 | $O(n^3)$ | $O(1)$ | 只用来说明「三个下标」 |
| 哈希凑第三个数 | $O(n^2)$ | $O(n)$ | 去重更绕，不比双指针好写 |

$n$ 最大 3000，$O(n^2)$ 大约是 $9 \times 10^6$ 次加法，能过；$O(n^3)$ 会超时。排序是原地的，额外空间是答案本身。

## 易错点

- **去重写在指针移动之前**：`while nums[left] == nums[left+1]` 如果在 `append` 之前做，会把当前这个合法的 `left` 跳掉，漏掉 `[-1,-1,2]` 这种有两个相同数的解。
- **只去重外层**：`[-1,-1,2]` 只出现一次没问题，但 `[-2,0,1,1]` 一类数据会在内层反复交出 `[-2,1,1]`。左右指针命中后都要跳。
- **忘记排序就夹逼**：无序数组上「和太小就右移左指针」没有单调性，会漏解。
- **`nums[i] > 0` 写成 `>=`**：全 0 数组里固定值就是 0，写成 `>=` 会直接 `break`，漏掉 `[0,0,0]`。
- **用下标集合去重而不是比相邻值**：排序之后相邻比较就够了，再开一个 `set` 把三元组转成元组，既慢又说明去重位置没放对。
