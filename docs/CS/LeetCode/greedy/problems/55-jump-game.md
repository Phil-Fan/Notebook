# 55. 跳跃游戏

!!! abstract "题单坐标"
    **Hot 20 · 第 12 类「贪心」** ｜ 难度：中等 ｜ 标签：`贪心` `数组` `动态规划`

    一句话套路：维护 `reach = max(reach, i + nums[i])`。一旦当前位置已经超过 `reach`，前面所有跳法都到不了这里，直接失败。

## 题干

> [力扣 55. 跳跃游戏](https://leetcode.cn/problems/jump-game/)

给你一个非负整数数组 `nums`，你最初位于数组的**第一个下标**。数组中的每个元素代表你在该位置可以跳跃的最大长度。

判断你是否能够到达最后一个下标，如果可以，返回 `true`；否则，返回 `false`。

**示例 1**

```text
输入：nums = [2,3,1,1,4]
输出：true
解释：可以先跳 1 步，从下标 0 到达下标 1，然后再从下标 1 跳 3 步到达最后一个下标。
```

**示例 2**

```text
输入：nums = [3,2,1,0,4]
输出：false
解释：无论怎样，总会到达下标为 3 的位置。但该下标的最大跳跃长度是 0，所以永远不可能到达最后一个下标。
```

**提示**

- `1 <= nums.length <= 10^4`
- `0 <= nums[i] <= 10^5`

## 思路

站在下标 `i`，下一步能落到 `[i, i + nums[i]]` 里的任意一格（`nums[i]` 是上限，不是必须跳满）。能到达的下标集合因此是一个从 0 开始的前缀：如果 0 到 `i` 都能到，而 `i+1` 不能到，那更远的位置也不用看了。

维护一个整数 `reach`：从已经检查过的位置出发，最远能覆盖到哪。扫到 `i` 时：

- `i > reach`：这一格本身到不了，返回 `false`。
- 否则用 `i + nums[i]` 尝试把 `reach` 拉远。
- `reach` 一旦盖住最后一个下标，就可以返回 `true`，后面的格子不用再看。

这是贪心而不是「每次都跳最远的那一档」。真正被保留的信息只有最远边界，具体从哪一格跳过来不影响「能不能到终点」。交换论证：任意一条能到终点的路线，它经过的每个下标都不超过当时的 `reach`；如果 `reach` 在终点之前就停滞，任何路线都会卡在同一道 0 上。

示例 2 里下标 3 的值是 0，走到它时 `reach` 停在 3，下一格 `i = 4 > 3`，失败。示例 1 里 `reach` 的变化是 `2 → 4`，下标 1 就把终点盖住了。

**走一遍示例 1。** `nums = [2,3,1,1,4]`。

| i | nums[i] | i ≤ reach？ | 更新后的 reach |
|:--|:--------|:------------|:---------------|
| 0 | 2 | 0 ≤ 0 | max(0, 0+2) = 2 |
| 1 | 3 | 1 ≤ 2 | max(2, 1+3) = 4 |
| — | — | 4 已经是最后一个下标 | 返回 true |

示例 2 `[3,2,1,0,4]`：`reach` 依次变成 3、3、3、3，到 `i = 4` 时 `4 > 3`，返回 false。

## 代码（带注释）

> 按力扣提交格式写：一个 `Solution` 类。只用内置类型。

```python
class Solution:
    def canJump(self, nums: list[int]) -> bool:
        reach = 0
        last = len(nums) - 1
        for i, step in enumerate(nums):
            if i > reach:
                return False
            reach = max(reach, i + step)
            if reach >= last:
                return True
        return True
```

`reach` 的初值是 0，因为起点不需要跳就能站上去。单元素数组 `last = 0`，第一轮就 `reach >= last`，返回 true。循环里的 `return True` 是提前结束，删掉它、只在循环外返回，结果一样，只是会把终点后面的格子也扫完——本题没有「后面」。

## 复杂度

| 写法 | 时间 | 空间 | 什么时候用 |
|:-----|:-----|:-----|:-----------|
| 维护最远可达 | $O(n)$ | $O(1)$ | 默认 |
| 从后往前看「最左一个能跳到这里的位置」 | $O(n)$ | $O(1)$ | 和 [45. 跳跃游戏 II](https://leetcode.cn/problems/jump-game-ii/) 的写法更接近 |
| `dp[i]` 表示能否到达 i | $O(n^2)$ | $O(n)$ | 只用来说明状态，`n = 10^4` 会超时 |

每个下标只看一次，`nums[i]` 只参与一次加法。不是 $O(n \cdot \max nums[i])$：不用把每一档跳法都枚举出来。

## 易错点

- **先更新 reach 再判断 `i > reach`**：顺序反了的话，一个本来到不了的格子会用自己的 `nums[i]` 把 `reach` 续上。必须先问「我站得上去吗」。
- **`nums[i] == 0` 立刻失败**：0 只说明不能从这里往更远跳。如果 `reach` 已经超过 `i`，从前面某一格可以飞过这个 0。`[2,0,0]` 能到终点。
- **必须跳满 `nums[i]`**：题目是「最大长度」，短跳是允许的。贪心也不需要真的选出跳几步，只维护边界。
- **从下标 1 开始扫**：起点的步数被漏掉，`[2,0]` 会误判成到不了。
- **和跳跃游戏 II 混用**：II 问的是最少跳数，要在 `reach` 的边界上再数一次「当前这一跳能覆盖到哪」。本题只问能不能。
