# 写作

## Related Work

### 一、放哪儿比较好？

- 如果自己认为已经在 Introduction 中把问题与参考文献的关系阐释得十分清楚，可以放到后面。
- **放在前面的好处：** 对 Introduction 中的创新性起到支撑作用，对审稿人进行再一次强化。
- **放在后面的好处：** 不吸引读者注意力，不占用主要篇幅，直接进入主题。

### 二、如何写 Related Work

**首先，要对自己当前文章的背景有深入的了解**，从不同维度对主题进行划分，同一类主题进行归类：

- 什么叫做深入的了解？
- 可能的有哪几块相关的工作？
- 比如说，你的工作是结合了 A+B，也牵扯到了 C，那么就得分子章节（subsection）来讨论 A、B、C 的相关工作。

**其次，要对相关工作进行简要总结：**

- **问题 1：** 老师，我该怎么总结啊？是不是去抄一下原文摘要或者介绍？
    - **答：** 不要抄，要把文章看一遍，通过自己的理解对文章进行总结，从自己的角度去评价论文。不要罗列论文，不要写成流水账；从时间、逻辑上写出一种递进的关系；可以在最后对某一类的文章进行总结。
- **问题 2：** 老师，每篇文章写多少总结？
    - **答：** 一般是一句话，不要写得太细节了；两句话也行；三句话就有点多了。如果文章十分相关，可以多写点；如果并不是特别相关，可以半句话带过。
- **问题 3：** 老师，我该如何措辞呢？
    - **答：** 写得时候要注意，所有的措辞都是对你自己文章的创新性提供支撑的，不要对别人的文章进行过度吹捧，也不要对其进行过度批评打压。

**最后，最关键的，要进行总结，并 "Justify 自己文章的 novelty"**（从代码直接总结？）：

- 总结得好与坏，非常能体现出作者的学术水平，以及对科研内容的理解。

**切忌让人觉得你是在拼接工作**：A 类的工作没有考虑 B，B 类的工作没有考虑 A，C 类工作没有考虑 B……所以咱们就做个 A+B+C。这样子必须从几个方面阐释创新性：

- 从机理的角度分析和阐释
- 从消融实验的角度分析和阐释
- 同时在写 Introduction 介绍的地方，一定要把机理讲清楚，进行一定的 High-Level 的抽象，在 Related Work 中详细提 A、B、C 相关工作

**如果发生撞车怎么办？** Paper 写完了，在 arXiv 上发现一篇类似的，咋办？心态崩了：

- 一定要 Justify 你的 novelty

### 三、浅谈从 Related Work 做科研

- **导师给了我一篇文章，让我以这篇文章为基准开展研究**
- **我对这个领域完全非常陌生，怎么办？** 首先，确定一篇经典论文：
    - IEEE Trans 顶刊，CCF-A 顶会，Citation 引用量，发表年份，发表单位/学校（比如说系统 5 年，AI 3 年）
    - 做两件事情：
        - 去看这篇文章 Cite 的论文（Depth-First Search, DFS），这样可以快速地了解这篇文章是“抄”的谁的，并快速了解本领域内权威文章。
        - 去 Google 搜索同类型的论文（Breath-First Search, BFS），这样可以快速地了解同类型的文章。
        - 去 Google 搜索有哪些最新的文章引用了这篇文章，他们都做得是什么，可以了解这个领域的发展方向，有没有人的 Idea 跟你的重了。
- **花时间，花时间，花时间！** 保持阅读，不是刷微信公众号、知乎做科研。
- **Paper 是看不完的，最后需要整理出一个 Finite Set of Papers：**
    - 有同学会担心：老师我真的很害怕，自己做了半天，跟别人的重了，别人发出来了。只要你不是抄的，一般不太会，至少技术细节不会。
    - 看了 100 篇 Paper，纯拍脑袋，形成初步想法。
    - 最后锁定 2-3 篇经典 Paper，重现别人实验，发现问题，形成初步想法。
    - 不断地与导师讨论，不断地自我思考，捋顺逻辑，分清主次。
    - **-> 安全 -> 需要搞明白怎么运行的 -> 正规赛道**

## Introduction

### 浅谈 Introduction 写作

- **Intro 是文章中最重要的部分之一，会直接影响审稿人的第一印象**
    - 一般高手都是最后再写 Introduction 的（或者直接由导师来完成撰写）
- **主要分为研究背景、提出观点、主要内容、贡献总结等几块：**
    - **研究背景：** 完成从大背景到具体研究小背景的快速聚焦
        - 研究背景中需要引用之前的文章，但是不展开讲具体细节，只进行高度的浓缩和凝练，讲 High-Level 的东西
        - 切忌在研究背景中展开长篇大论的叙述，需要直入主题（-> 我的个人风格）
        - 比如，之前的文章是做 GPU 多卡并行计算时间预测的，就不需要展开探讨什么是数据并行、模型并行，需要假设审稿人具备这方面的知识
    - **提出观点：** 提出之前文章的不足，完成从研究背景到提出观点的转折
    - **主要内容：** 从 High-Level 的层面描述提出的具体设计，通常可以写成第一点、第二点、第三点，需要与贡献的总结进行区分
    - **贡献总结：** 主要对文章的创新性作出总结，比如某领域的开山之作、在方法上的创新、最后实验部分的效果，可以添加一些数字
    - 新尝试的写法：以提问的方式（国内通常所说的科学问题），引出 Challenge

### Introduction 写作注意事项

- **切忌不能有 Typo**：如果有 Typo，审稿人的第一印象会很差，大概率会被拒稿
- 注意美式/英式英文混用（Organization/Organisation）
- **切忌避免出现口语化的词和写作方法：**
    - And 出现在句首；缩略词的使用如 it's、that's、there're 这类，正规英文写作中需要写全
    - 区分什么是偏口语化的用词：A lot of works、so......、by the way、but、because
        - Because 可以替换成什么？
        - But 可以替换成什么？
    - 切忌定义太多的缩写（Acronym），容易把人搞晕，比如动不动就定义一个：
        - Base Station (BS)、Energy Harvesting Base Station (EHBS)、Data Collection Base Station (DCBS)....... 要 minimize 缩写的定义增加可读性，比如之后的文章中不会用到的可以不进行定义
- **注意中文中顿号的使用**：英文中没有顿号，几个词通常是用逗号连接，最后的那个用 and
