# Native Sparse Attention

trainable 的精髓在于 Training

> [Native Sparse Attention: Hardware-Aligned and Natively Trainable Sparse Attention](https://arxiv.org/abs/2502.11089) — DeepSeek-AI，2025.02。实验平台是 27B 的 DeepSeekMoE 骨干（72 个路由专家 + 2 个共享专家），约 260B tokens 预训练。它是一个新注意力层的研究论文，不是任何已发布模型的检查点。

Natively trainable Sparse Attention

MHA / MQA / GQA / MLA 见 [01](./01-MHA.md)、[02](./02-MQA.md)、[03](./03-GQA.md)、[04](./04-MLA.md)。续训加装版本的 DSA 见 [06](./07-DSA.md)。

## 它拆的是哪一条约束

看注意力的效率要分三条互不相干的轴：

- **共享程度**：多少查询头共用一份 KV（MHA → MQA → GQA）。
- **缓存宽度**：每个 token 在缓存里占多少元素（MLA 的 $d_c + d_R = 576$）。
- **参与计算的 token 数**：每个查询真正和多少个历史位置做完整注意力。

MLA 动的是第二条。序列继续变长时，前两条都救不了第三条：缓存照旧随 $L$ 线性涨，每个查询仍然要扫完整条历史。论文引用的理论估算说，解码 64k 上下文时 softmax 注意力占掉总延迟的 70–80%，而解码是访存瓶颈，不是算力瓶颈。

所以 NSA 的立场很直接：既然贵在把 KV 从 HBM 搬到片上，就让每个查询只搬一小部分历史。**缓存本身不变小，变小的是每次搬多少。**

## 三条支路

每个查询 $q_t$ 的历史被重映射成三份 key/value 集合，注意力只在它们的并集上做：

| 支路 | 粒度 | 看什么 | 论文取值 |
|------|------|--------|----------|
| 压缩 compression | 块级 | 粗粒度全局 | 块长 $l=32$，步长 $d=16$ |
| 选择 selection | 更细的块 | 命中该查询的少数块 | 块长 $l'=64$，top-$n=16$ |
| 滑窗 window | token 级 | 最近邻 | $w=512$ |

**压缩支路。** 把相邻 $l$ 个 token 的 key 用一个学习到的 MLP（带块内位置编码）压成一条块级 key。相邻块重叠，步长 $d < l$，避免信息在切块处碎掉。压缩条目数约为 $\lfloor (t-l)/d \rfloor + 1$，仍随 $t$ 增长，只是除以 $d$。

**选择支路。** 序列切成 $l'=64$ 的选择块，每个查询挑分数最高的 $n$ 块。关键点是分数不另算：压缩支路算出的 softmax 分数 $\mathbf{p}_t^{\text{cmp}}$ 直接当块级重要性用。省掉的正好是「再跑一遍打分」那一遍。$n=16$ 里固定包含第 1 个初始块和 2 个局部块，等于是硬保底。

**滑窗支路。** 最近 $w=512$ 个 token 全要，包括压缩块内部还没被压掉的细节。语言模型强烈偏爱近邻，这条不能省。

## 三支怎么合

不是拼接，是门控加权：

$$
o_t = \sum_{c \in \{\text{cmp},\text{slc},\text{win}\}} g_t^{c} \cdot \operatorname{Attn}\left(q_t,\ \tilde{K}_t^{c},\ \tilde{V}_t^{c}\right),
\qquad
g_t^{c} = \sigma\!\left(\mathrm{MLP}(x_t)\right)
$$

门控输入是当前 token 的隐状态，每条支路一个标量。模型自己学「这一步该信全局摘要、该信选出来的块、还是该信最近 512 个 token」。三条支路并行做注意力，只在输出处合并，所以三个 kernel 可以各自优化。

## 每个查询要搬多少 token

设查询位置为 $t$，三支加起来的上界是

$$
N_t = \underbrace{\left\lfloor \frac{t-l}{d} \right\rfloor + 1}_{\text{压缩}} \;+\; \underbrace{n \cdot l'}_{\text{选择}} \;+\; \underbrace{w}_{\text{滑窗}}
$$

代进论文的取值，64k 时是 $4096 + 1024 + 512 = 5632$；全注意力要搬 65536 个 token，比值约 11.6。论文那张表里 8192 / 16384 / 32768 / 65536 四个长度对应 2048 / 2560 / 3584 / 5632 个 token 的访存量，加速比 4× / 6.4× / 9.1× / 11.6×，数字对得上。

严格写出来，复杂度是 $O(L^{2}/d + L(n l' + w))$：压缩那一项仍然是二次的，只是被 $d=16$ 除掉；选择和滑窗是线性的。宣传口径里的「近似线性」指每个查询的预算近似常数，不要真按 $O(L)$ 去证。

!!! note "被追问「压缩支路不还是二次的吗」"
    是，但常数小 16 倍，而且压缩条目是共享的：压一次，所有查询复用。真正随长度爆炸的那部分——对每个 token 做完整 key 点积——已经被预算 5632 的并集替代了。

## 为什么这条能从头训

早先的稀疏注意力大多是「先训全注意力，推理时再剪」，或者只在推理阶段丢 KV。NSA 的卖点是训练和推理用同一个稀疏模式：

- 前向只对被选中的块做注意力，反向只对同一批块回传梯度，两个方向都稀疏。论文因此说它省的是**预训练算力**，不只是推理成本。
- 稀疏模式由压缩分数动态决定，是学出来的，不是固定的带状掩码。
- 从预训练就稀疏，模型不会遇到「训练看全文、推理看不见」的分布错位。

硬件侧有三件事做不对就换不成墙钟时间：

1. **按 GQA 分组加载查询。** 同一组查询头共享同一份稀疏 KV 块，按 GQA 组加载才能合并访存；按时间相邻的查询块加载会得到互不相交的 KV 块，访存全碎。
2. **块对齐。** kernel 的块长整除选择块长 $l'$，Tensor Core 才跑得满。
3. **访存连续。** 选中的块按块连续搬运，而不是逐 token 做 scatter。

论文的 kernel 是 Triton 写的，对比对象是同后端的 FlashAttention-2，这样加速比不是实现差异带来的。

## 实验结果

- 27B 骨干、约 260B tokens 在 8k 上预训练，再用 YaRN 续到 32k 做长上下文训练和 SFT，两个模型都训到收敛。
- 通用基准平均 0.456，全注意力基线 0.443；MMLU 0.565 vs 0.567，GSM8K 0.520 vs 0.486，DROP 0.545 vs 0.503。
- 长上下文平均 0.469 vs 0.437。同等稀疏度下赢过 H2O、InfLLM、Quest 和 Exact-Top（后者用真实分数选 top-$n$，相当于上界参考）。
- 速度：**论文报告** 64k 长度下解码约 11.6×、前向约 9.0×、反向约 6.0×。这三个数字性质不同：11.6× 是按访存量推算的期望值（5632 vs 65536），9.0× / 6.0× 是实测 kernel。
- 一个容易漏掉的公平性细节：CoT 那组只和全注意力比，因为 H2O / Quest / infLLM 这些方法不支持训练，没法在同等条件下对比。

## 和 DSA、CSA / HCA 分清楚

名字像，位置完全不同：

| | NSA | DSA（[06](./07-DSA.md)） | CSA / HCA（V4） |
|--|-----|--------------------------|------------------|
| 怎么进模型 | 从头预训练一个新层 | 给已有 MLA 模型续训 | V4 自己的注意力层（预览） |
| 减什么 | 每个查询看的 token 数 | 每个查询看的 token 数 | 先把序列压成更少的槽，再稀疏或稠密 |
| 载体 | 独立的新注意力 | 装在 MLA 的 MQA 模式上 | 压缩槽上的注意力 |
| 状态 | 研究论文 | V3.2 上线 | V4 上线（预览） |

一句话：NSA 证明「稀疏注意力可以从头训、而且不丢质量」，DSA 证明「选 token 这件事能用最低接入成本装进一个已经训好的模型」。不要说成 V3.2 用了 NSA 的层。

## 面试里怎么收束

> NSA 是 DeepSeek 2025 年的稀疏注意力论文，不是任何线上模型的层。它给每个查询三条支路：32 块长 / 16 步长的重叠压缩出块级 key，用压缩分数选 64 大小的块 top-16，再加 512 的滑窗，三支输出用 MLP + sigmoid 的门控加权合并。64k 下每个查询只需搬 5632 个 token 的 KV，论文报告解码约 11.6×、前向约 9.0×、反向约 6.0×，而且从预训练就稀疏，所以反向也省。和 DSA 的区别是：NSA 从头训新层，DSA 是续训加装在 MLA 上的 indexer + top-k。

## MoBA

通过将上下文分块（历史段落），并使用门控机制将 token 选择性地路由到最相关的块，来解决传统注意力机制的计算低效问题。
