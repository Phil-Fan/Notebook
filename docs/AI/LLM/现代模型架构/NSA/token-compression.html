NSA 的 Token Compression：把 l 条 key 折成 1 条

注意力每一步的贵，不在算力，在 把 KV 从显存搬到片上：位置 t 的查询要和前面每一条 key 打分，序列多长就要搬多少条。压缩支路换个思路——把连续 l 个 token 的 key 用一个学出来的 MLP φ 折成一条块级 key，于是每个查询要看的条目从 t 条变成约 t/d 条。

下面用缩小版演示：t = 24、l = 8（块长）、d = 4（步长）；论文实际是 l = 32、d = 16。盯住三件事：块怎么滑、φ 怎么把 8 条压成 1 条、压完还剩几条。

为什么是 t−l 而不是 t：块要完整地落在 1…t 里，最后一块的起点最多到 t−l，所以可切的整块数是 ⌊(t−l)/d⌋。它约等于 t/d，所以每个查询的粗看成本降到约 1/d。另外，公式从 i=1 起算，最前面 d 个 token 不进压缩块；有的实现从 i=0 起（覆盖 k1:l），条数会多一条，不影响量级。

为什么步长 d 要比块长 l 小

把鼠标放到某个 token 上，看它同时属于几个块。

d < l 让相邻块重叠 l−d 个 token，每个 token 最多被 ⌈l/d⌉ 个块覆盖。这样即使某个 token 在「错」的块边界上，也还能在相邻块的摘要里出现一次——切块不会把信息切断。

换成论文的尺度

论文实际取值 l = 32、d = 16，序列 64k。

t65536 l / d32 / 16 块数 = ⌊(t−l)/d⌋⌊65504/16⌋ = 4094 ≈ t/d4096 全注意力每个查询65536 条 压缩支路每个查询4094 条 ≈ 1/16

注意 4094 和 4096 的差别只是 减去块长再取整：量级上就是 t/d。
另一个关键点：压缩只算一次，所有查询复用——24 条 key 压成 4 条，不是每个查询各压一遍。

四个容易混的点

  • 压缩 ≠ 缓存变小。原始 K/V 还在，cache 照样是 t 条。变小的是「每个查询每一步要搬多少条」。缓存宽度由 MLA 管，参与计算的 token 数由 NSA / DSA 管，两条轴正交。
  • φ 不是平均池化。它是带块内位置编码的可学习 MLP，参数在所有块之间共享；模型自己学「这 l 条里哪些信息值得留给粗粒度表示」。
  • 压缩只负责「全局粗看」。块级 key 看不出块内细节，所以 NSA 还要选择支路（挑 top-n 个细块）和滑窗支路（最近 w 个 token），三支输出用门控加权相加。压缩分支算出的分数还会被选择分支直接复用。
  • 压缩项仍是二次的。条目数 ≈ t/d，所以复杂度是 O(t²/d) —— 常数小了 d 倍，不是真线性。「近似线性」指每个查询的预算近似常数。
一句话收束：压缩支路以 l 为块长、d 为步长在 key 序列上滑窗，每块用 φ 折成一条块级 key k̃i；一共 ⌊(t−l)/d⌋ ≈ t/d 条，叠成 K̃ ∈ ℝdk×⌊(t−l)/d⌋。查询 qt 只对这 ≈t/d 条打分，拿到一个便宜的粗粒度全局视野，精读留给选择与滑窗。
