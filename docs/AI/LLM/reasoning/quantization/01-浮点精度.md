# 浮点与低精度格式

FP4、FP8、BF16 都是**一个数占多少 bit，以及这些 bit 怎么分给符号、指数、尾数**。名字里的数字是总位数。它们不是新的层，也不是注意力变体。

[CSA](../../现代模型架构/CSA.md) 里的三处用法可以先对上号：indexer 的 QK 点积走 FP4，打分 \(I_{t,s}\) 用 BF16 保存，KV cache 里 RoPE 那几维留 BF16、其余用 FP8。下面先把格式本身讲完，再回到这三处为什么能这么分。

## 一个数怎么被拆开

IEEE 浮点和它的低精度变体都是同一条式子。设符号位 \(S\)、指数位字段 \(E\)、尾数位字段 \(M\)（\(m\) bit），指数偏置为 \(b\)：

\[
x =
\begin{cases}
(-1)^S \times 2^{E-b} \times \left(1 + M / 2^{m}\right) & E \neq 0 \quad \text{（正规数）} \\[4pt]
(-1)^S \times 2^{1-b} \times \left(M / 2^{m}\right) & E = 0 \quad \text{（次正规数或 0）}
\end{cases}
\]

正规数的尾数隐含一个前导 1，所以 \(m\) bit 尾数实际有 \(m+1\) bit 有效数字。\(E = 0\) 且 \(M = 0\) 是 0。部分格式另外留出全 1 指数来表示 Inf 和 NaN。

两个独立的量：

- **动态范围**由指数位数决定。指数多，最大数更大、最小正规数更小。
- **精度**由尾数位数决定。尾数多，相邻两个可表示数靠得更近。

把尾数让给指数，范围变宽、间隔变稀，BF16 相对 FP16 就是这么换的。把两边一起砍，就是 FP8、FP4。

## 对照

相对间隔指的是：1 和比它大的下一个可表示数之间的差距。FP32 的 \(2^{-23}\) 约等于 \(1.2 \times 10^{-7}\)。

| 格式 | bit | 符号 / 指数 / 尾数 | 偏置 | 约最大绝对值 | 1 附近的相对间隔 | 常见位置 |
|------|-----|--------------------|------|--------------|------------------|----------|
| FP32 | 32 | 1 / 8 / 23 | 127 | \(3.4 \times 10^{38}\) | \(2^{-23}\) | 主权重、优化器、累加 |
| TF32 | 19（不单独存） | 1 / 8 / 10 | 127 | 同 FP32 | \(2^{-10}\) | Tensor Core 内部的矩阵乘 |
| FP16 | 16 | 1 / 5 / 10 | 15 | 65504 | \(2^{-10} \approx 0.1\%\) | Volta 一代的训练精度 |
| BF16 | 16 | 1 / 8 / 7 | 127 | 同 FP32 量级 | \(2^{-7} \approx 0.78\%\) | 现在的默认训练精度 |
| FP8 E4M3 | 8 | 1 / 4 / 3 | 7 | 448 | \(2^{-3} = 12.5\%\) | 权重、激活 |
| FP8 E5M2 | 8 | 1 / 5 / 2 | 15 | 57344 | \(2^{-2} = 25\%\) | 梯度 |
| FP6 E2M3 | 6 | 1 / 2 / 3 | 1 | 7.5 | \(2^{-3} = 12.5\%\) | Blackwell，本目录模型还没用 |
| FP6 E3M2 | 6 | 1 / 3 / 2 | 3 | 28 | \(2^{-2} = 25\%\) | 同上 |
| FP4 E2M1 | 4 | 1 / 2 / 1 | 1 | 6 | \(0.5 = 50\%\) | indexer、MXFP4 权重 |
| INT8 | 8 | 整数 | — | 由 scale 定 | 均匀格点 | 推理权重、激活 |
| INT4 | 4 | 整数 | — | 由 scale 定 | 均匀格点 | GPTQ、AWQ |
| NF4 | 4 | 正态分位点 | — | 由 scale 定 | 近零更密 | QLoRA |

比特图（`S` 符号，`E` 指数，`M` 尾数）：

```text
FP32      S EEEEEEEE MMMMMMMMMMMMMMMMMMMMMMM
BF16      S EEEEEEEE MMMMMMM
FP16      S EEEEE MMMMMMMMMM
FP8 E4M3  S EEEE MMM
FP8 E5M2  S EEEEE MM
FP4 E2M1  S EE M
```

## BF16、FP16、TF32

三档 16 bit 上下的格式，差在指数和尾数怎么分。

**FP16**（IEEE binary16）尾数 10 bit，1 附近能分到大约 0.1%。指数只有 5 bit，最大正规数是 65504，最小正规数约 \(6.1 \times 10^{-5}\)。训练时激活和梯度很容易超出这个范围，所以 FP16 混合精度要做 loss scaling：反向前把损失乘一个常数，优化器更新前再除回去。

**BF16**（bfloat16）指数 8 bit、偏置 127，和 FP32 同一套阶。最大数仍在 \(10^{38}\) 量级，训练不用 loss scaling。尾数只剩 7 bit，1 的下一个可表示数是 \(1 + 2^{-7} = 1.0078125\)。从 FP32 转到 BF16 就是留下符号、指数和尾数的高 7 位，丢掉低 16 位。A100 及之后的 Tensor Core 用它做矩阵乘。

**TF32** 是 Ampere 起 Tensor Core 的乘加格式，内存里仍是 FP32。送进矩阵乘之前，尾数从 23 bit 收到 10 bit，指数保持 8 bit。范围跟 FP32，尾数精度跟 FP16。它不出现在 checkpoint 或 KV cache 里。

## FP8：E4M3 和 E5M2

8 bit 装不下「又宽又细」。OCP 的 FP8 因此拆成两种，Hopper 的 Tensor Core 两种都能做输入。

| | E4M3 | E5M2 |
|--|------|------|
| 字段 | 1 符号 + 4 指数 + 3 尾数 | 1 符号 + 5 指数 + 2 尾数 |
| 偏置 | 7 | 15 |
| 最大正规数 | 448 | 57344 |
| 最小正规数 | \(2^{-6} = 1/64\) | \(2^{-14}\) |
| Inf | 没有 | 有 |
| NaN | 只有 `S 1111 111` 这一种 | 指数全 1 且尾数非 0 |

E4M3 把指数全 1 的大多数编码仍当作正规数，只有尾数也全 1 才是 NaN，所以最大值能到 \(2^{8} \times 1.75 = 448\)。尾数 3 bit，1 的下一个数是 1.125。权重和激活的数值分布落在这个范围里，多出来的尾数比多出来的指数有用。

E5M2 的指数和 FP16 一样宽，尾数只够把每个阶分成 4 档（含隐含的前导 1 则是更粗的相对步长 \(2^{-2}\)）。梯度的数量级跳得大，这个范围更合适。

Transformer Engine 的经典分法：前向的权重和激活用 E4M3，反向的梯度用 E5M2。整张张量共用一个 FP32 scale 时，梯度往往装不进 E4M3。分块缩放把每个小块各自对齐之后，E4M3 就够用了。[DeepSeek-V3](../../frontier/10-deepseek-v3.md) 走的是后一条：激活按 \(1 \times 128\)、权重按 \(128 \times 128\) 各带一个 FP32 scale，元素一律 E4M3；沿内积方向每 128 个元素把部分和提升到 FP32，弥补 FP8 Tensor Core 累加尾数不够。

口语里的「FP8」多半指 E4M3。PyTorch 里对应 `torch.float8_e4m3fn` 和 `torch.float8_e5m2`（`fn` = finite，E4M3 没有 Inf）。AMD MI300 是另一套 `fnuz` 编码，偏置和 NaN 的摆法不同，和 OCP 的比特不能混用。

## FP4：E2M1 能表示的全部数

4 bit 是 1 个符号、2 个指数、1 个尾数，偏置 1。没有 Inf，也没有 NaN。正数只有 8 个：

| 编码 `S EE M` | 含义 | 值 |
|---------------|------|----|
| `0 00 0` | 0 | 0 |
| `0 00 1` | 次正规数 | 0.5 |
| `0 01 0` | \(2^{0} \times 1.0\) | 1 |
| `0 01 1` | \(2^{0} \times 1.5\) | 1.5 |
| `0 10 0` | \(2^{1} \times 1.0\) | 2 |
| `0 10 1` | \(2^{1} \times 1.5\) | 3 |
| `0 11 0` | \(2^{2} \times 1.0\) | 4 |
| `0 11 1` | \(2^{2} \times 1.5\) | 6 |

负数是符号位取反，另有一个 \(-0\)。一共 16 个编码、15 个不同的实数。超出 \(\pm 6\) 的数饱和到 \(\pm 6\)。

1 和 1.5 之间没有任何编码，相对间隔是 50%。0.01 和 100 都表示不了。所以 FP4 几乎不单独出现，旁边一定有一个 scale，真实值是 \(\text{scale} \times q\)。

## 缩放

低精度元素的范围是固定的。scale 把一块真实数值平移到这个范围里：

\[
x \approx s \cdot q
\]

\(q\) 是 FP4 / FP8 / INT 元素，\(s\) 是这块的 scale。块越小，一块内部的最大和最小越接近，量化误差越小，scale 本身越占空间。

| 方案 | 一块多大 | scale 用什么 | 平均每个元素 |
|------|----------|--------------|--------------|
| 每张量 / 每通道 | 整行或整张 | FP32 | 元素位数 + 可忽略的 scale |
| V3 的分块 FP8 | 激活 \(1\times128\)，权重 \(128\times128\) | FP32 | 约 8 bit |
| MXFP8 / MXFP4 | 连续 32 个元素 | UE8M0（8 bit，纯 2 的幂） | FP8 为 8.25 bit，FP4 为 4.25 bit |
| NVFP4 | 连续 16 个元素 | 每块一个 E4M3，整张再一个 FP32 | 约 4.5 bit |

**UE8M0** 是 8 bit 无符号指数，偏置 127，取值 \(2^{-127}\) 到 \(2^{127}\)，没有尾数、没有 0。全 1 是 NaN。反量化就是给元素的指数加一个整数。[DSA](../../现代模型架构/07-DSA.md) 的 index key 按 128 维一块量化，scale 用的就是这种纯 2 的幂：反量化不必做乘法，抬一下指数即可。

**MX** 是 OCP 的微缩放格式。一块 32 个数共享一个 UE8M0。MXFP4 的元素是上面的 E2M1，32 个数占 \(32 \times 4 + 8 = 136\) bit，平均 4.25 bit。因为每 32 个数就能重新对齐一次，FP4 那组 \(\{0, 0.5, 1, 1.5, 2, 3, 4, 6\}\) 只需要覆盖这一小块的形状。

**NVFP4** 是 Blackwell 上 Transformer Engine 的 4 bit 格式。元素仍是 E2M1，但一块只有 16 个数，块 scale 用 E4M3（有尾数，不限于 2 的幂）。E4M3 自己最大只到 448，所以整张张量再配一个 FP32 scale。块更小、scale 更细，平均比特略高于 MXFP4。

[V4](../../frontier/12-deepseek-v4.md) 后训练把路由专家权重收到 MXFP4，indexer 的 QK 也在 FP4 里做。

## 整数：INT8、INT4、NF4

整数量化的格点是均匀的。对称形式 \(x \approx s \cdot q\)，\(q\) 落在一个固定整数区间里：INT8 常用 \([-127, 127]\)，INT4 常用 \([-8, 7]\) 或 \([-7, 7]\)。非对称形式再加一个零点 \(z\)，\(x \approx s \cdot (q - z)\)。GPTQ、AWQ 通常按组量化，一组 128 个权重共用一个 scale。

同样 4 bit，浮点和整数的格点形状不同。E2M1 的点在 0 附近相对密（0、0.5、1），到了 4 和 6 就很稀。INT4 的 16 个点（含符号后）间距恒定。权重往往集中在 0 附近、同时带少量离群值，所以有 Tensor Core 之后，FP8 / FP4 在大矩阵乘上比同比特整数更容易保住精度。离群值本身靠分块 scale 或 SmoothQuant 这类把激活的幅度折进权重的办法处理。

**NF4**（NormalFloat4）是 QLoRA 的 4 bit 码本：16 个重建值取标准正态的分位点，让码本匹配「权重近似正态」这个假设。一块（常见 64 个）共享一个 absmax scale，scale 自己还可以再量化一次（double quant）。计算前要反量化回 BF16，它不是 Hopper / Blackwell 上那种直接进 Tensor Core 的 FP4。

## 训练和推理里各放在哪

一次混合精度训练里，格式按「这个数还要不要继续被很小的更新修正」来分：

| 位置 | 常见格式 | 原因 |
|------|----------|------|
| 主权重、Adam 的矩 | FP32，显存紧时部分用 BF16 | 更新量比权值小几个数量级，尾数太短会把更新舍成 0 |
| 前向矩阵乘 | BF16，或 FP8 E4M3 | 要尾数；范围靠 BF16 的指数或靠 FP8 的 scale |
| 反向梯度的矩阵乘 | BF16，或 FP8 E5M2 | 梯度的数量级跨度大 |
| 送进 Tensor Core 的 FP32 乘 | TF32 | 存储不变，只改乘加内部的尾数 |
| KV cache | FP8；RoPE 维常留 BF16 | 省的是带宽；旋转对那几十维的尾数更敏感 |
| 只用来排序的分数 | FP4，甚至再收到 BF16 | 要的是相对次序 |
| 部署时的权重 | FP8、MXFP4、NVFP4、INT4 | 权重读一次、算一次，比特直接变成显存和带宽 |

敏感算子经常留在高精度：embedding、输出头、MoE 门控、softmax、归一化。掉点时先查这些，再查被量化的 GEMM。

### 回到 CSA 那句

[CSA](../../现代模型架构/CSA.md) 的 indexer 对每个已完成的槽做 64 头、128 维的 ReLU 点积，分数只用于 top-k，没有 softmax。绝对值偏 10% 通常不改变谁进前 512。所以 QK 可以在 FP4 里算。后训练的 QAT 再把分数 \(I_{t,s}\) 从 FP32 收到 BF16：BF16 的指数仍盖得住分数的数量级，尾数对排序足够，选择快一倍，论文报告 KV 召回率 99.7%。

KV cache 要参与真正的注意力加权，误差会进输出。压缩槽是 512 维，其中位置只写在最后 64 维，输出端还要用 \(-t\) 的旋转把绝对位置折回相对位置。这 64 维用 BF16，其余用 FP8：旋转那一段留尾数，剩下的向量留动态范围给 scale。

## 面试里怎么收束

> FP32 是 1+8+23。BF16 是 1+8+7，指数和 FP32 相同，所以训练不用 loss scaling，代价是尾数只剩 7 bit。FP16 是 1+5+10，尾数更细，但最大只有 65504。FP8 有两种：E4M3 最大 448，给权重和激活；E5M2 最大约 5.7 万，给梯度。FP4 是 E2M1，正数只有 0、0.5、1、1.5、2、3、4、6，必须配 scale。MXFP4 是每 32 个数共享一个 2 的幂 scale。CSA 把 FP4 用在只排序的 indexer 上，把 BF16 留给 RoPE 维和打分，其余 KV 用 FP8。
