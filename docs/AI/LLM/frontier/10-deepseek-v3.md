# DeepSeek-V3

> [DeepSeek-V3 Technical Report](https://arxiv.org/abs/2412.19437) — DeepSeek，2024.12。671B 总参数，每个 token 激活 37B。预训练约 14.8T tokens，完整训练 2.788M H800 GPU hours。

结构继承 [V2](09-deepseek-v2.md)。这篇报告代表的是：同一套块可以训到闭源前沿，而且训练策略本身有可讲的改动。

## 块没有换

仍然是 MLA 加 DeepSeekMoE。V3 的 MoE 配置是：256 个路由专家里选 8 个，再加 1 个始终激活的共享专家。前几层保留稠密 FFN，后面才是 MoE。共享专家吃通用模式，路由专家保持细粒度。

R1 沿用这个块。R1 的贡献是 GRPO 和推理强化学习，面试里不要把 MLA 说成 R1 发明的。

## 无辅助损失的负载均衡

MoE 的老问题是路由崩溃：少数专家接到几乎所有 token。常见补救是加一项负载均衡辅助损失。它能把 token 摊开，但梯度会干扰主损失，专家变得没那么专。

V3 把均衡从损失函数里拿出来，改成每个专家一个偏置 \(b_i\)：

1. **选择**时，把 \(b_i\) 加到亲和度上，再做 top-k。
2. **合并**时，门控权重不用这个偏置，任务梯度看不见它。
3. **更新**时，专家比期望更忙，就把 \(b_i\) 调低；太闲就调高。

三句话要一起说完。只说「加了个 bias」会被追问这个 bias 进不进梯度。

## Multi-Token Prediction

除了下一个 token，模型还挂若干顺序的 MTP 模块。每个模块看到主模型的表示，以及已经预测出的前一个未来 token 的嵌入，再预测更远的一个 token。训练损失是这些额外预测的加权和。

它代表的判断是：预测未来多个 token 会逼表示学到更完整的局部结构，主模型的下一 token 损失也会受益。推理时这些模块可以丢掉。硬件侧的后续工作把 MTP 头当作投机解码的草稿模型，那是部署，不是 V3 块本身。

## FP8

训练用 FP8 混合精度，用来降低算力和显存，而不是一种新层。面试里把它和 MLA、MoE 分开：前两者是结构，FP8 是数值格式。报告同时强调训练过程没有不可恢复的 loss spike，也没有回滚。

## 面试里怎么收束

> V3 的块就是 V2。新的是无辅助损失均衡：偏置只参与选专家，不进门控权重。MTP 是额外的未来 token 目标。671B 里激活 37B，256 选 8 加 1 个共享专家。账单公开，是这代开源模型第一次把训练成本本身变成论点。
