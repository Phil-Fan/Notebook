# Qwen3

> [Qwen3 Technical Report](https://arxiv.org/abs/2505.09388) — 阿里巴巴，2025.05。稠密模型从 0.6B 到 32B，MoE 为 30B-A3B 与 235B-A22B。旗舰 235B 总参数，每个 token 激活 22B。

## 这篇论文代表什么

块几乎就是 Qwen2.5。报告要证明的是：思考模式和非思考模式可以放进同一个权重，不必再维护一个聊天模型和一个专门的推理模型。小模型则靠旗舰蒸馏，而不是各自从零预训练出同样的能力。

架构题里要主动把这句话说在前面。如果面试官追问块，再讲下面两处干净的改动。

## 相对 Qwen2 的两处结构改动

稠密模型仍是 GQA、SwiGLU、RoPE、Pre-Norm RMSNorm。改动是：

- 去掉 Qwen2 的 QKV bias。
- 在注意力里加上 QK-Norm，把查询和 key 归一化，压住训练时的注意力 logit。

这是稳定性修改，不是一种新注意力。注意力仍然是 GQA，不是 MLA。

| 稠密模型 | 层数 | 头（Q / KV） | 绑定词嵌入 | 上下文 |
|----------|------|--------------|------------|--------|
| 0.6B | 28 | 16 / 8 | 是 | 32K |
| 1.7B | 28 | 16 / 8 | 是 | 32K |
| 4B | 36 | 32 / 8 | 是 | 128K |
| 8B | 36 | 32 / 8 | 否 | 128K |
| 14B | 40 | 40 / 8 | 否 | 128K |
| 32B | 64 | 64 / 8 | 否 | 128K |

KV 头固定在 8，查询头随宽度增加。这就是 GQA 的缩放方式：缓存头数不跟查询头一起涨。

## MoE：拿掉共享专家

MoE 与稠密模型同一套注意力。沿用 Qwen2.5-MoE 的细粒度切分，但不再设共享专家。两个 MoE 都是 128 个专家里激活 8 个，上下文 128K。

| 模型 | 层数 | 头（Q / KV） | 专家（总 / 激活） |
|------|------|--------------|-------------------|
| 30B-A3B | 48 | 32 / 4 | 128 / 8 |
| 235B-A22B | 94 | 64 / 4 | 128 / 8 |

均衡用的是全局 batch 上的负载损失，用来鼓励专家专精。这和 [DeepSeek-V3](10-deepseek-v3.md) 的无辅助损失偏置是两条路：Qwen3 仍把均衡写进损失，只是把统计范围放到全局 batch，并放弃共享专家。

## 思考模式不是一层

同一个模型用聊天模板进入思考或非思考。思考预算限制推理阶段可以花多少 token，用来在延迟和效果之间做选择。这是推理时的计算分配，权重里没有一条单独的「思考层」。

换块发生在下一代。[Qwen3-Next](14-qwen3-next.md) 才把大部分层换成 Gated DeltaNet。

## 面试里怎么收束

> Qwen3 证明模式切换和蒸馏，不证明新块。结构上是 GQA 加 QK-Norm，去掉 QKV bias。MoE 是 128 选 8，没有共享专家。和 DeepSeek 比，它没有 MLA，也没有把均衡损失换成偏置。
